Project guide

Project Guide | Fab Ops Yield Control Tower

Free manufacturing yield-control readiness worksheet for shift evidence and exception queues. This guide follows the repository’s synthetic-only SPC, advisory disposition, executed replay, and integrity-envelope evidence path.

Reviewed 2026-08-13. This page is derived from checked-in repository evidence and links back to its source.

Synthetic advisory demo

This repository is a reviewable, non-production FastAPI demonstration. Its fab values are hand-authored synthetic fixtures; they are not MES, FDC, historian, wafer-map, customer, measured-yield, or forecast data.

Human authority is never delegated. Every disposition is advisory, human_approval_status remains not_recorded, and the API reports material_state_changed: false. An HMAC envelope proves payload integrity and shared-key authenticity only; it is not a signed human approval.

Evidence-first evaluation path

  1. GET /api/fab-ops/v1/control-plan — inspect the versioned Western Electric rules, packaged fixture SHA-256, and authority boundary.
  2. GET /api/fab-ops/v1/lots/lot-8812/disposition — execute the synthetic fixture case and inspect WECO, q-time, TAT, routing, blockers, lineage, and the unchanged material state.
  3. GET /api/fab-ops/v1/evals/replays — inspect executed assertion objects and their actual values. If this API is unavailable, there is no replay-pass evidence.
  4. GET /api/fab-ops/shift-handoff/signature — export an HMAC integrity envelope whose signed manifest binds the fixture hash, control-plan/disposition contracts, recommendation, WECO rules, and synthetic flow states.
  5. POST /api/fab-ops/shift-handoff/verify — post the exported payload unchanged. Verification hashes the caller-presented manifest, validates every exact outer-envelope field, and rejects extras; it does not rebuild a trusted local copy.

The canonical case is HOLD_FOR_CONTAINMENT. A clean caller-supplied series with no flow_context is routed to ENGINEERING_REVIEW, not release advice, because an authoritative hold/q-time state is absent. Only an explicitly non-production request with complete synthetic flow evidence and no displayed blockers or review flags can receive RELEASE_WITH_SAMPLING, which still requires authorized human review.

Run and verify locally

git clone https://github.com/KIM3310/fab-ops-yield-control-tower.git
cd fab-ops-yield-control-tower
make run

# strict lint, type, coverage, installed-wheel, smoke, and repository checks
make verify-strict

make run explicitly selects credential-free demo mode. An unset mode is locked. Non-demo profiles fail closed on operator and signing routes until credentials are configured.

Deployment boundary

The repository includes optional container, Kubernetes, Terraform, and AWS adapter examples; their presence is not a claim that a production service or live fab integration exists. The Kubernetes production Deployment references an externally created semiconductor-ops-secrets Secret and probes /ready. Its SQLite topology is deliberately single-replica with Recreate updates and a ReadWriteOnce persistent volume; no HPA is shipped because horizontal file-backed SQLite writers would split or contend for the audit ledger. A reviewed shared database is required before scaling out. No deployable Secret values are checked in. Follow the Kubernetes configuration guide.

AWS writers are disabled unless both AWS_ACCESS_KEY_ID and AWS_SECRET_ACCESS_KEY are configured; SQS and DynamoDB also require their target variables. Authentication is checked before guarded audit export routes invoke any writer.
